# extracted/

Game data that our own tools write from your ROM, in forms people read and edit. It is game data, so nothing here except this file and `.gitkeep` enters git (tenet 9): only the tools and the files that say how to read the data are committed.

| Path | What | Written by |
|---|---|---|
| `AWRE/assets/maps/` | One YAML file per campaign, Versus, War Room and Survival map. Editable; `maps.py pack` builds the map tables in ov000 from them (`docs/maps.md`). | `tools/maps.py unpack`, run by `make setup` |
| `AWRE/assets/sound/` | The sound archive `sound_data.sdat`, one file per archive file, plus `sound.yaml` with every entry. `sound.py pack` rebuilds the archive byte for byte from them (`docs/sound.md`). | `tools/sound.py unpack`, run by `make setup` |
| `AWRE/music/` | Every song, sound effect and the stream as MP3. Output only; regenerated when the archive or zxtune changes (`docs/sound.md`, "Export"). | `tools/sound.py export`, run by `make music`, and by `make setup` outside linked worktrees when ffmpeg is installed |
| `AWRE/data/<module>/<symbol>.inc.c` | The values of data objects, which the C in `src/` includes inside its initializers (`#include "data/main/data_02139288.inc.c"`; the compiler runs with `-i extracted/AWRE`). Regenerated by every build from `config/AWRE/data_inc.txt`; do not edit. | `tools/data_inc.py`, run by the build |

In an agent's worktree, `AWRE/assets/` is a link to the main checkout's copy (`tools/wt_setup.sh`), and `AWRE/data/` is the worktree's own, since the build writes it from that worktree's config.

Not to be confused with `extract/`, which holds the ROM split into its parts by dsd as the build's input. The two may be renamed later.
